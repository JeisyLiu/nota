Stream the transcript live, show the steps, and let the user stop

Three things were missing from the recording flow: text appeared only after the
whole clip was transcribed, the pipeline was an opaque "processing..." line, and
there was no way to call it off once started.

Live transcription

A new `/ws/transcribe` socket takes raw 16 kHz mono PCM and answers with partial
text. Measured here on CPU int8: tiny 0.46 s per pass, base 0.9 s, small 2.8 s.
The preview therefore uses `base` (a 3 s window transcribes in about a third of
its own duration, so it keeps up with speech) and the authoritative pass still
uses the configured `small`. Whisper emits traditional Chinese for short windows
unless primed, so a simplified-Chinese `initial_prompt` is prepended -- verified
to switch the output with no measurable cost.

Cold-loading the preview model takes about 20 s, which would look like a broken
feature on the first press, so it is warmed on a background thread at startup.

The preview is a hint, never the transcript: the app closes the socket when the
finger lifts and the real transcript still comes from the uploaded file, so a
dropped preview costs nothing.

The recorder grew a `readChunk()` method that hands back PCM captured since the
last call, so the same recording feeds both the preview and the WAV without
capturing twice.

Steps and stopping

The app now opens the detail page the moment a job is submitted. That page polls
while the job is non-terminal, so state and tool calls appear as they happen
instead of all at once at the end, and it owns the stop button.

Cancelling is its own state, not a failure: `cancelled` is terminal, never
retried, and the reserved request is refunded. The worker checks between phases
so it stops paying for work nobody wants.

Fixing that exposed a lost-update race. The worker holds a transaction open for
the whole run, so a cancel committed in between was overwritten when the worker
committed: the job sprang back to `agent_running` and the already-refunded
request got spent anyway. State transitions are now compare-and-set
(`set_job_state_if`), and the worker aborts quietly when it loses the race.

Also fixed: two tests pinned "tomorrow" to a hardcoded date and would have
started failing the day the wall clock moved past it. They now pin a fixed clock
through `AppContainer.use_clock`, which the eval suite already needed.

Verified end to end: streaming partials accumulate as speech arrives ("明天。" ->
"明天下午三点" -> the full sentence) and cancel closes the socket cleanly; the
detail page opens live with the stop button; pressing stop yields `cancelled`, the
badge flips to 已停止 and the quota comes back (used 2 -> 1). 57 backend tests
pass, analyze clean, 11 widget tests pass.
