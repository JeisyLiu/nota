Let admins file a task on a user's behalf

The user detail page existed but was never routed: I had written the renderer and
forgotten the route entry, so the "详情" link just landed back on the list. It now
has its own path, hidden from the sidebar, and shows the account, its 14-day usage,
its todos and its reminders.

That page gained the one write action the console offers. Support staff often need
to add a task while on the phone with a customer, and making them log in as that
customer would be worse in every way, so an admin can file a todo or a reminder
for a specific user. The rows are ordinary todos/reminders, so they show up in the
user's own app list immediately.

A browser `datetime-local` value carries no timezone. Storing it naive would make
the reminder sweep compare timestamps of two different kinds, so it is anchored to
the *user's* timezone before it is written, and a test asserts the stored value
ends in +08:00.

Also:
  - the user-detail payload now returns that user's todos and reminders, so the
    admin can see the effect of what they just filed;
  - scripts/verify.ps1 checks the filing endpoint end to end. That check uses an
    ASCII title on purpose: Windows PowerShell 5.1 decodes a JSON response without
    a charset as Latin-1, so a Chinese comparison fails in the harness rather than
    on the server. Exact UTF-8 behaviour is covered by pytest.

Verified in headless Chrome: the detail page renders all six panels, submitting the
form raises the toast, the new todo appears in the list, and no JS errors are
logged. 90 tests pass and verify.ps1 is green.
