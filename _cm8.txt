Give the app real accounts: login, register, logout

The app identified itself with a hardcoded X-User-Id header, so "personal data" was
whoever the build said it was. It now has the same accounts as the console.

Backend
  - POST /api/auth/register creates a plain user on the free plan. Role and plan
    are decided server-side and the request cannot ask for more, so this endpoint
    can never mint an administrator. Username 2-32 non-space characters, password
    at least 6, duplicate -> 409.
  - Login now also returns the token in the body. The browser keeps using the
    HttpOnly cookie; a native client cannot, since package:http does not persist
    cookies across launches.
  - identity.current_account() accepts Authorization: Bearer before the cookie.
    Same sessions table, so expiry and revocation behave identically, and
    /api/admin/* stays session-only either way.
  - Logout revokes every credential the request carries (bearer and cookie).

App
  - lib/auth/session.dart: AppUser plus a SessionStore over shared_preferences.
  - lib/app_gate.dart owns the single NotaClient and decides between the login page
    and the home page; any 401 clears the session and returns to login with a
    notice.
  - lib/pages/login_page.dart: login/register in one screen, client-side validation,
    friendly error mapping, and a demo-account shortcut.
  - lib/pages/profile_page.dart: avatar, name, plan, today's quota, record/todo/
    success metrics, account details, change password, logout.
  - HomePage shows the signed-in name and an avatar that opens the profile; it no
    longer disposes the client, which now belongs to the gate.

Two things found while testing, both fixed:
  - the gate could sit on a spinner forever if local storage failed, because the
    bootstrap future was fire-and-forget. It now has a 5s timeout and falls back to
    the login page. (On this machine the sandbox denies writes to
    C:\Users\...\AppData\Roaming\com.nota, which is exactly how the hang surfaced;
    on a normal launch storage works and no notice appears.)
  - the initial character used String.characters without importing it; runes are
    used instead so a non-BMP name is not sliced in half.

Verified: 99 backend tests and 25 Flutter tests pass, analyze is clean, and the
Windows build was driven with real mouse events - login as zhangwei shows 张伟 with
quota 2/10 and seeded history, the avatar opens the profile page, and logout
returns to the login page and revokes the server session (checked in the sessions
table). scripts/verify.ps1 gained register/bearer checks and still passes.
